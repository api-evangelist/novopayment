# NovoPayment

> NovoPayment is a Miami-headquartered banking-as-a-service and embedded-finance platform serving
> banks, fintechs, retailers and payment companies across the Americas. It publishes 15 OAuth2-secured
> REST contracts (163 operations, OpenAPI 3.0) across six product families on its developer hub.

Generated: 2026-09-17 by API Evangelist (https://apievangelist.com) from NovoPayment's own published
OpenAPI documents and developer hub. NovoPayment publishes no llms.txt of its own; this file is a
third-party index, not a provider document.

## Access model

- Authentication: OAuth 2.0 client credentials. POST https://sandbox-api.novopayment.com/oauth2/token
  (form-encoded grant_type=client_credentials, client_id, client_secret) returns a BearerToken with
  expires_in 1799 seconds. No scopes are published.
- Headers: X-Tenant-Id (required), X-Transaction-Id (trace id, NOT idempotency), X-Request-Id,
  X-Time-Zone.
- Environments: sandbox (self-service after registration + project creation), UAT and production
  (granted on request after NovoPayment reviews the project). Credentials differ per environment.
- Errors: first-party {code, message, datetime} envelope on every response. The ten-character code
  (HTTP status.product segment.detail) carries the outcome, not the HTTP status. Not RFC 9457.

## What NovoPayment does not publish

- No idempotency key on any of the 163 operations.
- No rate limits, no 429 response, no RateLimit-* headers.
- No pagination parameters on any list operation.
- No prices, plans or rate card — commercial terms go through the commercial team.
- No status page, no public changelog, no deprecation or versioning policy.
- No SDK on any public package registry; no public GitHub repositories.
- No /.well-known/ document on any host, no MCP server, no A2A agent card.
- Certifications are named in the developer hub footer (PCI, ISO 27001/27017/27018, SOC 1, SOC 2,
  Visa Ready) with no attestation documents or trust centre.
